● Section 1: Overall Architecture

  Three layers, each with a single responsibility:

  Angular (Browser)
    └─ SQLConsoleComponent
         ├─ MonacoEditor (SQL input)
         ├─ FabSelectorComponent (multi-select, 14 fabs)
         ├─ ContextSQLSelectorComponent (YAML templates)
         └─ ResultsComponent (Flat Table / Diff / Pivot)
              └─ FabQueryService (SSE client)

  Golang Backend
    └─ /api/fabs/query (POST)  →  /api/fabs/stream/{id} (GET SSE)
         └─ /internal/fabquery/   ← shared by ALL multi-fab features
              ├─ engine.go        fan-out goroutines, collect via channel
              ├─ testdb.go        trial run on test sidecar
              ├─ validator.go     SELECT-only enforcement
              └─ rownum.go        auto-wrap with ROWNUM <= :limit
  
  Python Sidecar Adapter (per Fab + Test DB)
    └─ HTTP endpoint wrapping Oracle cx_Oracle SDK
         POST /query  →  { rows: [...], columns: [...] }

  Request lifecycle:
  1. User submits SQL + selected fabs
  2. Backend validates (SELECT-only) → test DB trial run → issue stream ID
  3. Frontend opens SSE connection on stream/{id}
  4. Backend fans out goroutines (one per fab), results flush as SSE events
  5. Frontend accumulates into signal<FabResult[]>(), table renders incrementally

  State model（全在 SQLConsoleComponent）：
  selectedFabs   = signal<string[]>([])
  sql            = signal<string>('')
  rowLimit       = signal<number>(100)
  queryId        = signal<string | null>(null)
  fabResults     = signal<FabResult[]>([])

● Section 3: Backend Data Flow

  主流程：

  POST /api/fabs/query
    body: { sql, fabs, rowLimit, namedParams }
    │
    ├─ validator.go: 解析 SQL AST，確認為 SELECT（非 DDL/DML）
    │    └─ 失敗 → 400 { error: "only SELECT allowed" }
    │
    ├─ rownum.go: 包裹 → SELECT * FROM (...user sql...) WHERE ROWNUM <= :limit
    │
    ├─ testdb.go: 送 Test DB sidecar 試跑（timeout: 5s）
    │    └─ 超時或錯誤 → 400 { error: "query too slow or invalid" }
    │
    ├─ 建立 queryId（UUID），存入 in-memory map（TTL 5min）
    └─ 200 { queryId }
  
  GET /api/fabs/stream/{queryId}
    │
    ├─ 設定 SSE headers（text/event-stream, no-cache）
    ├─ engine.go: 對每個 fab 啟動 goroutine
    │    └─ goroutine: POST sidecar /query → 結果送入 channel
    │
    ├─ SSE flush loop:
    │    for result := range resultChan {
    │      write event: { fab, rows, columns, status }
    │      flush()
    │    }
    └─ 所有 goroutine 完成 → 送 event: { type: "done" } → 關閉連線

  Sidecar 通訊：
  每個 Fab 對應一個 sidecar endpoint（從 config 讀取 URL map）。Goroutine 逾時設 30s per fab；失敗的 fab 送 { fab, status: "error", message } event，不阻斷其他 fab
  的結果。

  這部分看起來 OK 嗎？

● Section 4: Error Handling

  分層處理原則：快速失敗在前，部分失敗在後。

  ┌──────────────────────┬───────────────────┬─────────────────────────────────┐
  │        情境           │        層級        │              行為               │
  ├──────────────────────┼────────────────────┼─────────────────────────────────┤
  │ 非 SELECT 語法        │ Backend（POST）      │ 400，立即回傳，不進入 Test DB          │
  ├──────────────────────┼──────────────────────┼────────────────────────────────────────┤
  │ Test DB 超時（>5s）   │ Backend（POST）      │ 400，說明 query 過慢                   │
  ├──────────────────────┼──────────────────────┼────────────────────────────────────────┤
  │ Test DB 語法錯誤      │ Backend（POST）      │ 400，回傳 Oracle 錯誤訊息                              │
  ├──────────────────────┼──────────────────────┼────────────────────────────────────────────────────────┤
  │ Named param 未填      │ Frontend             │ 送出前 disable 按鈕，提示必填                          │
  ├──────────────────────┼──────────────────────┼────────────────────────────────────────────────────────┤
  │ ROWNUM 超出 300       │ Frontend + Backend   │ Frontend 截斷；Backend 二次驗證                        │
  ├──────────────────────┼──────────────────────┼────────────────────────────────────────────────────────┤
  │ 單一 Fab sidecar 失敗 │ Backend（SSE event） │ { fab, status:"error" } → 繼續其他 fab                 │
  ├──────────────────────┼──────────────────────┼────────────────────────────────────────────────────────┤
  │ 所有 Fab 失敗         │ Frontend             │ 顯示全域錯誤 banner                                    │
  ├──────────────────────┼──────────────────────┼────────────────────────────────────────────────────────┤
  │ SSE 連線中斷          │ Frontend             │ FabQueryService 偵測 EventSource.onerror，顯示重試提示 │
  ├──────────────────────┼──────────────────────┼────────────────────────────────────────────────────────┤
  │ QueryId 不存在/過期   │ Backend（SSE）       │ 404，frontend 顯示「查詢已過期，請重新執行」           │
  └──────────────────────┴──────────────────────┴────────────────────────────────────────────────────────┘

  Partial failure UX：
  每個 fab 有獨立的 FabStatusChip（loading → done / error）。失敗的 fab 在表格中顯示 error row，不影響其他 fab 的結果渲染。使用者可看到「12/14 廠區成功」。
  
  這部分看起來 OK 嗎？
